온다정 — 시니어클럽 출퇴근·전화 서비스

노인일자리 수행기관(시니어클럽)에서 어르신 수천 명의 출퇴근을 매일 기록하고, 그 기록으로 활동일지와 급여까지 이어지게 하는 서비스입니다. 스마트폰이 어려운 어르신은 전화 한 통으로, 그 밖의 분은 링크로 출퇴근합니다.

  • 역할서비스개발자 — 백엔드·화면·교환기·서버 운영
  • 상태여러 기관에서 운영 중
  • 기술FastAPI · PostgreSQL · Asterisk · Kamailio · Flutter
  • 기간2026 ~ 지금

구조

기관마다 전화번호와 교환기가 따로 있고, 모든 자료는 기관(tenant)으로 갈립니다. 전화 출근은 교환기에서 출근 API 까지 한 번에 이어집니다.

푼 문제

1. 출근 시간에 전화가 몰리면, 어르신은 끊긴 줄 안다

문제
출근 시각에 전화가 한꺼번에 들어오면 받고 나서 첫 안내가 나올 때까지 조용한 시간이 길어졌습니다. 가짜 참여자 300명으로 동시 통화를 재 보니 90통이면 19.9초가 조용했습니다. 출근은 찍혔지만, 어르신은 20초 동안 아무 소리가 없으면 끊긴 줄 압니다.
원인
0.2초마다 교환기 채널 상태를 떠서 단계별로 쟀습니다. 안내 재생은 멀쩡했고, 통화마다 파이썬 스크립트를 새로 띄우고 HTTPS 연결을 새로 맺는 구간이 늘어지고 있었습니다. 가상 CPU 를 호스트에 20~37% 빼앗기는 것도 겹쳤습니다.
한 일
스크립트를 통화마다 띄우지 않고 상주하는 FastAGI 서버로 바꾸고, API 연결 40개를 미리 맺어 두었습니다. 멈추면 예전 방식으로 돌아가는 길도 남겼습니다.
결과
같은 90통에서 조용한 시간 가운데값 2.8초 · 최대 4.6초 (19.9초에서).

2. 기관이 둘이 되자 남의 기관 자료가 보였다

문제
두 번째 기관을 붙인 날, 관리자 화면에 다른 기관 참여자가 섞여 나왔습니다. '전부 보기' 권한이 '우리 기관 전부'가 아니라 'DB 전부'였습니다. 기관이 하나일 땐 드러나지 않던 구멍입니다.
한 일
권한 범위와 별개로 모든 질의에 기관 조건을 언제나 거는 함수를 만들었습니다. 기관을 모르면 열지 않고 FALSE 로 닫습니다. 같은 눈으로 전수 점검해 로그인 없이 열린 길까지 14곳을 막고, "INSERT·SELECT·UPDATE·DELETE 에 항상 기관 조건"을 팀 규칙 문서로 남겼습니다.
결과
이름이 겹치는 기관이 8쌍 있어도 이름이 아니라 기관 id로만 가르는 구조가 됐습니다.

3. 기관마다 다른 명단 엑셀

문제
기관마다 명단 엑셀 모양이 달라(옛 형식 5가지, 통합 양식 7장) 올릴 때마다 칸이 조용히 버려지거나 요일이 하루씩 밀리는 일이 생겼습니다.
한 일
통합 양식 변환기를 만들고, 실제 기관 파일을 가명으로 바꾼 사본으로 회귀시험을 묶었습니다. 같은 파일을 두 번 올려도 아무 일이 없게 만들고, 반영 직전·직후 자료를 짝으로 백업해 그 기관만 되돌릴 수 있게 했습니다.
결과
회귀시험 48 → 85건 통과·실패 0. 양식을 건드리면 이 시험부터 돌립니다.

4. 클라우드 이전과 직원용 앱

한 일
서비스 서버를 오라클 클라우드로 옮기며 전환·되돌리기 절차를 스크립트로 만들었습니다. 담당자가 밖에서 쓰는 Flutter 직원용 앱 시제품(카카오 로그인, 디자인 토큰 한 곳)도 만들었습니다.
결과
직원 앱 단추 전수 시험 66/66 · 정적 분석 경고 0.

배운 것

  • 어르신 서비스에서는 '처리됐다'보다 '들었다'가 중요합니다. 기록이 맞아도 20초 침묵은 실패입니다.
  • 경계 구멍은 고객이 하나일 때 숨어 있다가 둘이 되는 날 터집니다. 규칙은 첫날부터 코드에 둡니다.
  • 조용히 버려지는 칸이 가장 무섭습니다. 그래서 변환기는 '모르는 머리글'부터 봅니다.

회사 서비스라 코드는 비공개 저장소에 있습니다. 구조·수치는 운영하며 직접 잰 값이고, 고객 기관 정보는 넣지 않았습니다.
