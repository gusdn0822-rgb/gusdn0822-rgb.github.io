1. 출근 시간 첫 안내 대기 78% 단축 — 20.9초 → 4.6초

문제
출근 시각에는 전화가 한꺼번에 몰립니다. 어르신은 전화를 받은 뒤 소리가 없으면 끊긴 줄 알기 때문에, 이 서비스에서는 첫 안내까지의 대기가 곧 품질입니다. 큰 행사를 앞두고 몰리는 상황을 미리 재현했습니다.
원인
교환기 안에서 가상 통화로 동시 90통을 만들고(가상 참여자 300명), 0.2초마다 채널 상태를 기록해 단계별 시간을 측정했습니다. 병목은 안내 재생이 아니라 통화마다 스크립트를 새로 띄우고 서버 연결을 새로 맺는 구간이었습니다.
해결
스크립트를 상주 FastAGI 서버로 바꾸고, API 연결 40개를 미리 열어 두는 커넥션 풀을 붙였습니다. 상주 서버에 문제가 생기면 기존 경로로 자동 전환되며, 응답을 받기 전 실패에서만 전환해 출근이 두 번 기록되지 않게 했습니다.
판단
평균이 아니라 가장 늦게 안내를 듣는 분의 대기를 목표로 잡았습니다. 서버 처리량에 맞춰 동시 처리 수를 묶어, 중앙값은 조금 늘더라도 어떤 경우든 최대 대기가 일정하게 짧도록 맞췄습니다.
결과
동시 90통 최대 대기 20.9초 → 4.6초 · 동시 300통까지 끊긴 통화 0건. 자세한 글 보기 →

2. 멀티테넌트 — 기관 경계를 코드 규칙으로

문제
여러 기관이 한 서비스를 함께 쓰고, 이름이 같은 기관과 담당자도 실제로 있습니다. 이름으로 구분하는 순간 기관 사이의 경계가 흐려집니다.
해결
기관마다 전화번호·교환기·SIP 경로를 분리하고, 데이터는 기관 ID로만 구분합니다. 권한과 별개로 모든 조회에 기관 조건을 거는 공통 함수를 두고, 기관을 확인할 수 없으면 아무 작업도 하지 않도록 했습니다.
판단
기관마다 다른 운영 방식은 코드 분기 대신 명단 엑셀의 옵션 열로 받습니다. 모든 기능은 모든 기관에 공통으로 제공하고, 새 기관이 들어와도 코드를 고치지 않습니다.
결과
INSERT·SELECT·UPDATE·DELETE에 항상 기관 조건을 거는 원칙을 팀 코드 규칙으로 문서화해, 새 코드도 같은 기준으로 리뷰합니다.

3. 기관마다 다른 엑셀 5종을 통합 양식 하나로

문제
기관마다 명단 엑셀 형식이 달라, 담당자가 직접 양식을 맞추는 수작업이 반복됐습니다.
해결
시트 7장짜리 통합 양식과 변환기를 만들고, 가명 처리한 실제 파일로 회귀 테스트를 구성했습니다. 같은 파일을 두 번 올려도 결과가 같고(멱등), 반영 직전·직후를 백업해 기관 단위로 롤백할 수 있습니다. 인식하지 못한 열은 반영 전에 화면에서 먼저 알려 줍니다.
결과
회귀 테스트 85/85. 양식을 바꿀 때마다 이 테스트부터 돌립니다.

4. 운영 서버 클라우드 이전

해결
서비스 서버를 오라클 클라우드로 옮기며 전환·롤백 절차를 스크립트로 만들고, 기관마다 교환기를 나눠 배치했습니다. 전환 전후 데이터는 건수로 대조해 검증했습니다.
확장
같은 API 위에 현장 담당자를 위한 담당자 앱을 만들었습니다.

회고

  • 어르신 서비스에서는 '처리됐다'보다 '들었다'가 중요합니다. 기록이 정확해도 긴 침묵은 실패이므로, 최악의 경우를 기준으로 설계합니다.
  • 멀티테넌트의 경계는 리뷰 습관이 아니라 코드 규칙으로 지킵니다.
  • 엑셀처럼 사람이 만드는 입력은 회귀 테스트로 지킵니다.
