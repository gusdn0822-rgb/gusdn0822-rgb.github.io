온다정 담당자 앱 — 현장에서 일하는 담당자를 위해

노인 일자리 담당자는 사무실보다 현장에 있을 때가 많습니다. 오늘의 출근 현황, 다시 걸 전화, 걸려 온 전화의 어르신 정보를 휴대폰에서 바로 확인하는 앱을 설계부터 개발까지 맡았습니다. 웹 서비스와 같은 API를 씁니다.

화면

앱의 체험 모드 화면이에요. 이름과 기관은 모두 예시 데이터입니다.

핵심 기여

1. 디자인 토큰으로 웹과 같은 화면 기준

해결
간격·모서리·버튼 높이·글자 크기를 tokens.dart 한 파일로 모으고, 웹 서비스의 디자인 토큰과 값을 맞췄습니다. 화면 코드에는 숫자를 직접 쓰지 않습니다.
판단
어르신을 돕는 담당자용 앱이라 글자 16 이상, 터치 영역 48 이상, 말줄임 없이 끝까지 보여 주는 것을 기준으로 삼았습니다. 320px 작은 화면에서도 글자와 버튼이 잘리지 않게 맞췄습니다.
결과
자동 테스트 79/79 · 정적 분석 경고 0.

2. 카카오 로그인 + 서버 검증으로 기관 경계 지키기

해결
앱은 카카오 로그인 결과만 서버로 보내고, 서버가 카카오에 직접 확인한 전화번호로 담당자를 찾습니다. 여러 기관에 속한 담당자는 직접 고르게 하고, 이름으로는 찾지 않습니다.
판단
기관 경계는 앱이 아니라 서버가 지킵니다. 앱이 믿어도 되는 정보와 서버가 확인해야 하는 정보를 먼저 나눴습니다.
결과
실제 카카오 계정으로 로그인 → 서버 검증 → 홈까지 전 과정 동작을 확인했습니다.

3. 릴리스 빌드에서만 멈추던 로그인 추적

문제
디버그 빌드에서는 되던 로그인이 릴리스 빌드에서만 멈췄습니다.
원인
logcat으로 추적해 보니, 코드 축소(R8)가 리플렉션으로 호출되는 코드 두 곳(저장소 플러그인, Kotlin 코루틴)을 쓰지 않는 코드로 보고 지우고 있었습니다.
해결
지워진 클래스를 특정해 keep 규칙을 작성했습니다. 오류는 화면에 한 줄로 보여 주고, 원문은 로그로 남겨 다음 추적을 빠르게 했습니다.

회고

  • 체험 모드를 처음부터 넣어 두면, 실제 데이터 없이도 화면을 보여 주고 테스트할 수 있습니다.
  • 릴리스 빌드는 디버그와 다른 앱이라고 보고 따로 확인합니다.
