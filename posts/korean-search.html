초성과 한영 오타로 찾기, 그리고 조합 중 Enter

사내 메신저를 만들며 한국어 사용자에게 맞춘 세 가지 — 'ㄴㅎㅇ'으로 사람 찾기, 'skagusdn'을 '남현우'로 알아듣기, 한글을 조합하는 중에 누른 Enter.

2026년 10월 · JavaScript

1. 초성으로 찾기 — 낱말마다

한글 음절은 유니코드에서 0xAC00 부터 규칙적으로 놓여 있어서, 초성은 나눗셈 한 번으로 꺼낼 수 있습니다(초성 하나에 중성 21 × 종성 28 = 588 칸).

const CHO = 'ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ';
const choseong = s => [...s].map(ch => {
  const c = ch.charCodeAt(0) - 0xAC00;
  return c >= 0 && c < 11172 ? CHO[Math.floor(c / 588)] : ch;
}).join('');

choseong('남현우');   // 'ㄴㅎㅇ'

처음엔 이름·직무·채널명을 한 줄로 붙여 초성을 비교했더니, 낱말 경계를 건너 엉뚱한 것이 걸렸습니다(이모지 찾기에서 'ㅂㅅ'이 두 낱말에 걸쳐 맞음). 그래서 낱말마다 따로 초성을 비교합니다.

2. 영문 자판 오타를 한글로 — 두벌식 오토마타

한글 전환을 잊고 skagusdn 을 치는 일은 흔합니다. 자판 자리를 자모로 바꾸는 것까진 쉽지만(s→ㄴ, k→ㅏ, a→ㅁ …), 자모를 글자로 묶는 게 핵심입니다.

  • 받침 뒤에 모음이 오면 그 받침은 다음 글자의 첫소리로 넘어갑니다. ㄴㅏㅁㅎㅕㄴㅇㅜ → 남·현·우
  • 겹모음(ㅗ+ㅏ→ㅘ)과 겹받침(ㄹ+ㄱ→ㄺ)을 묶고, 겹받침 뒤에 모음이 오면 뒤쪽 자음만 넘깁니다.
  • Shift 는 된소리(Q→ㅃ)와 O→ㅒ, P→ㅖ 로 받습니다.

찾기는 한 함수로 모았습니다 — 그대로 들어 있나 → 초성인가 → 영문이면 한글로 바꿔서 들어 있나. 사이드바·@부르기·채널·할 일 찾기 등 13곳이 같은 함수를 씁니다. 찾는 곳마다 따로 만들면 결과가 어긋나기 때문입니다.

3. 조합 중에 누른 Enter

크롬·엣지에서 '안녕'의 '녕'을 조합하는 도중 Enter 를 누르면, keydown 이 isComposing = true 로 먼저 옵니다. 이걸 그냥 무시하면 Enter 를 두 번 눌러야 보내지고, 바로 보내면 마지막 글자가 빠집니다. 사파리는 순서가 반대(조합이 먼저 끝나고 Enter)입니다.

function enterSends(input, send) {
  let pendingAt = 0;
  input.addEventListener('compositionend', () => {
    // 조합 중 눌린 Enter 는 조합이 끝난 직후에 보낸다 — 1초 안에만
    if (pendingAt && performance.now() - pendingAt < 1000) setTimeout(send, 0);
    pendingAt = 0;
  });
  return e => {                       // keydown 에서 부른다
    if (e.key !== 'Enter' || e.shiftKey) return false;
    if (e.isComposing) { pendingAt = performance.now(); return true; }
    e.preventDefault(); send(); return true;
  };
}

'1초 안에만'을 둔 건, 걸어 둔 보내기가 한참 뒤 다른 글자의 조합 끝에 엉뚱하게 터지지 않게 하려는 것입니다. 확인은 브라우저 자동 조작으로 실제 조합 입력을 재현해서 했습니다.

정리

  • 한국어 입력은 '글자'가 아니라 자모와 조합의 문제로 보면 풀립니다.
  • 찾기 규칙은 한 함수로 — 화면마다 따로 만들면 사용자는 '여기선 되고 저기선 안 되는' 앱을 만나게 됩니다.
